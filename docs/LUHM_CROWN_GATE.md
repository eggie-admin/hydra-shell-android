# LuHm Crown Gate

`KAI9000_LUHM_CROWN_GATE_V2`

The Crown Gate is the evidence boundary for LuHm OS. It allows theatrical presentation without theatrical engineering claims.

## Authority chain

1. **Professor** authorizes consequential actions.
2. **Lum** plans, inspects, challenges assumptions, keeps source-of-truth alignment, and refuses fake GREEN.
3. **GitHub/source tests** prove the proposed source state is internally coherent.
4. **GitHub Actions forge** proves an explicitly authorized source state can compile and produce signed build evidence.
5. **Android** enforces package identity, signer continuity, version monotonicity, and user-confirmed installation.
6. **Physical hardware** proves launch, persistence, Secure Folder behavior, reboot behavior, and runtime integrations.

## Canonical tiers

- `WHISPER / GREEN`: read-only inspection/research/provenance. No mutation authority.
- `CROSSING / AMBER`: reversible Mirror Route staging with origin, mirror, delta, rollback, proof, and lineage. No Crown authority is gained.
- `RECKONING / RED`: compile/sign/install/canonical merge/publish/destructive/privileged/final source-of-truth promotion. Exact Professor authorization is required.

`POWER LEVEL != PERMISSION LEVEL` remains absolute.

## Evidence states

- `SOURCE_GREEN`: current proposed source matches active doctrine and passes source-contract tests.
- `AGENT_GREEN`: authority/no-self-approval/secret boundaries pass.
- `FORGE_GREEN`: APK build, signer, 16 KiB alignment, ABI, SDK levels, and packaged assets pass CI.
- `UPDATE_GREEN`: same package + same signer + higher versionCode contract passes.
- `DEVICE_GREEN`: current signed candidate is physically installed and launched on target hardware.
- `PERSISTENCE_GREEN`: save/reload and reboot observations are physically proven.

`FULL_GREEN` or `CROWN_ECLIPSE_GREEN` means every required state for the claimed scope has executed evidence. Source GREEN never implies build, install, device, or publication GREEN.

## Modular Sprite Cockpit

Canonical UI scales:

```text
SPRITE_BUBBLE <-> WIDGET_DECK <-> FULL_COCKPIT
```

All scales share one session/state tree. The visible realms are `GAME`, `ADMIN`, and `SYSTEM`. GAME state may change presentation only. It cannot trigger ADMIN mutation.

The cockpit may stage a typed `pending_reckoning`, but it may never execute or self-authorize RECKONING. Minimize/restore changes presentation scale only. It must not duplicate jobs, resend prompts, restart services, or repeat mutations.

Personal Reckoning Parley preserves ROLEPLAY VOICE + TRUTH STRIP + MACHINE ENVELOPE and the three-round `OPEN -> COUNTER -> RECKON` budget at every UI scale.

See `docs/LUHM_MODULAR_SPRITE_COCKPIT.md` for the source contract.

## Public release rule

Public publishing is opt-in and manual-only. Normal pushes, merges, source tests, and private update preparation must not publish public APKs or a public F-Droid mirror.

## Asset rule

Only LuHm/KAI-owned or explicitly redistribution-cleared assets may ship in a generally distributable APK. Community assets remain third-party and retain author/license/commit receipts. Unknown or mixed-provenance packs remain quarantined.

## Source-of-truth seal readiness

A final source-of-truth promotion is RECKONING. Before asking the Professor to seal it, the candidate should provide:

1. exact `luhmos-main` origin SHA;
2. exact feature/candidate head SHA;
3. source delta and rollback coordinates;
4. active doctrine alignment with no unresolved repository-doctrine drift;
5. modular widget-contract and state-pass tests GREEN;
6. GAME/ADMIN firewall test GREEN;
7. Parley three-layer/three-round contract GREEN;
8. no arbitrary shell, eval, background network fetch, secret material, or quarantined asset ingress in the modular presentation code;
9. a machine-readable seal candidate recording which build/device gates remain pending;
10. no claim that source readiness closes physical hardware gates.

A source-of-truth seal can truthfully mark `SOURCE_GREEN=true` while keeping `FORGE_GREEN`, `DEVICE_GREEN`, or `PERSISTENCE_GREEN` false/pending for the new candidate if those actions were not authorized or executed.

## Physical-device boundary

The intended Samsung device owns install, launch, touch/input, rotation, permissions, Secure Folder, save/reload, reboot/return, and update-continuity evidence. CI/build output cannot backfill these observations.

The crown is a gate, not a shortcut.
